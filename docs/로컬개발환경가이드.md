# AIStockQuote 로컬 개발 환경 가이드

이 문서는 프로젝트 루트의 Django 애플리케이션을 Windows와 PowerShell 환경에서 실행하는 방법을 설명합니다.

## 1. 사전 준비

다음 프로그램이 필요합니다.

- Python 3.12 권장
- Git
- PowerShell

설치 여부를 확인합니다.

```powershell
python --version
git --version
```

프로젝트의 Docker 이미지도 Python 3.12를 사용합니다. 패키지 호환성을 위해 로컬에서도 같은 버전을 권장합니다.

## 2. 프로젝트 받기

저장소를 처음 받는 경우 다음과 같이 진행합니다.

```powershell
git clone <repository-url> AIStockQuote
cd AIStockQuote
```

이미 프로젝트가 있다면 루트 디렉터리로 이동합니다.

```powershell
cd C:\Users\USER\Documents\AIStockQuote
```

루트에 `manage.py`, `requirements.txt`, `config/`, `apps/`가 있는지 확인합니다.

## 3. 가상환경 구성

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

PowerShell 실행 정책 때문에 활성화가 차단되면 현재 프로세스에만 실행 정책을 적용한 뒤 다시 활성화합니다.

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

가상환경을 종료할 때는 다음 명령을 사용합니다.

```powershell
deactivate
```

## 4. 환경변수 설정

예제 파일을 복사합니다.

```powershell
Copy-Item .env.example .env
```

`.env`에서 로컬 환경에 필요한 값을 설정합니다. `.env`는 Git에 커밋하지 않습니다.

### Django 기본 설정

```dotenv
DJANGO_SECRET_KEY=local-development-secret
DJANGO_DEBUG=true
DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1
DJANGO_CORS_ALLOWED_ORIGINS=
```

### AI 분석 설정

사용할 제공자의 API 키를 하나 이상 입력합니다. API 키가 없으면 AI 분석만 비활성화되고 나머지 기능은 사용할 수 있습니다.

```dotenv
ANTHROPIC_API_KEY=
OPENAI_API_KEY=
GEMINI_API_KEY=
AI_PROVIDER=
```

`AI_PROVIDER`에는 `anthropic`, `openai`, `gemini` 중 하나를 지정할 수 있습니다. 비워 두면 설정된 키를 기준으로 자동 선택합니다.

### 데이터베이스 설정

`POSTGRES_HOST`가 비어 있으면 프로젝트 루트의 `db.sqlite3`를 사용합니다. 기본적인 로컬 개발에는 SQLite를 권장합니다.

PostgreSQL을 사용하는 경우 다음 값을 설정합니다.

```dotenv
POSTGRES_HOST=localhost
POSTGRES_PORT=5432
POSTGRES_DATABASE=aistockquote
POSTGRES_USER=stock_app
POSTGRES_PASSWORD=<password>
```

PostgreSQL 연결 시 애플리케이션은 `stock,public` 검색 경로를 사용합니다.

## 5. 데이터베이스 초기화

현재 마이그레이션을 적용합니다.

```powershell
python manage.py migrate
```

관리자 계정이 필요하면 생성합니다.

```powershell
python manage.py createsuperuser
```

모델을 변경한 경우에는 마이그레이션을 생성하고 적용합니다.

```powershell
python manage.py makemigrations
python manage.py migrate
```

마이그레이션 누락 여부만 확인하려면 다음 명령을 사용합니다.

```powershell
python manage.py makemigrations --check --dry-run
```

## 6. 개발 서버 실행

프로젝트 루트에서 실행합니다.

```powershell
python manage.py runserver
```

주요 접속 주소는 다음과 같습니다.

- 애플리케이션: `http://127.0.0.1:8000/stock/`
- 루트: `http://127.0.0.1:8000/` — `/stock/`으로 이동
- Django 관리자: `http://127.0.0.1:8000/admin/`
- 애플리케이션관리자: http://127.0.0.1:8000/stock/stock-admin/

다른 포트를 사용하려면 포트 번호를 지정합니다.

```powershell
python manage.py runserver 8080
```

## 7. 코드 검사 및 테스트

Django 설정과 애플리케이션 구성을 검사합니다.

```powershell
python manage.py check
```

전체 Django 테스트를 실행합니다.

```powershell
pytest
```

특정 테스트만 실행하려면 파일이나 테스트 이름을 지정합니다.

```powershell
pytest tests/test_smoke.py
pytest tests/test_smoke.py::test_root_redirects
```

루트 `pytest.ini`는 현재 Django 테스트가 있는 `tests/`만 수집합니다. 이전 FastAPI 구현과 테스트는 `legacy_fastapi/`에 보존되어 있으며 현재 메인 테스트에 포함되지 않습니다.

## 8. 정적 파일

개발 서버에서는 Django가 정적 파일을 제공합니다. 배포 형태를 로컬에서 확인하려면 정적 파일을 수집합니다.

```powershell
python manage.py collectstatic --noinput
```

생성되는 `staticfiles/`는 빌드 결과이므로 Git에 커밋하지 않습니다.

## 9. Docker로 실행

Docker가 설치되어 있다면 다음과 같이 이미지를 빌드하고 실행할 수 있습니다.

```powershell
docker build -t aistockquote .
docker run --env-file .env -p 8000:8000 aistockquote
```

컨테이너는 Gunicorn으로 루트 Django 프로젝트의 `config.wsgi:application`을 실행합니다.

## 10. 자주 발생하는 문제

### `ModuleNotFoundError`가 발생하는 경우

가상환경이 활성화되어 있는지 확인하고 의존성을 다시 설치합니다.

```powershell
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### 패키지 설치 중 NumPy 또는 Pandas 빌드 오류가 발생하는 경우

Python 3.12 가상환경을 새로 만들고 `pip`을 업그레이드한 뒤 설치합니다. 프로젝트는 Python 3.12용 바이너리 wheel이 제공되는 NumPy 1.26.4와 pandas 2.1.4 이상을 사용합니다.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

### 데이터베이스 테이블 오류가 발생하는 경우

마이그레이션 상태를 확인하고 적용합니다.

```powershell
python manage.py showmigrations
python manage.py migrate
```

### 포트가 이미 사용 중인 경우

다른 포트로 실행합니다.

```powershell
python manage.py runserver 8080
```

### 관리자 로그인이 되지 않는 경우

관리자 계정을 새로 만들거나 비밀번호를 변경합니다.

```powershell
python manage.py createsuperuser
python manage.py changepassword <username>
```

## 11. 개발 작업 전 확인 목록

- 가상환경이 활성화되어 있는가
- `.env`가 생성되어 있는가
- `python manage.py check`가 통과하는가
- 최신 마이그레이션이 적용되어 있는가
- 변경 후 `pytest`가 통과하는가
- 비밀키, API 키, 비밀번호가 Git 변경 목록에 포함되지 않았는가
